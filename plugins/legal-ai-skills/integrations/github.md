# GitHub

## Required capability

Support authorised software and IP diligence using a specified GitHub organisation or repository. GitHub is evidence of repository activity; it is not, by itself, conclusive proof of legal ownership.

## Expected actions

- identify repository visibility, default branch and relevant dates;
- inspect licence files, contribution history and repository metadata;
- identify contributors, organisations and material external forks where supported;
- inspect dependency manifests and notices for open-source review;
- locate agreements, policies or source references stored in the repository;
- link each finding to a repository, commit, file or other stable locator.

## Scope and safeguards

Confirm organisations, repositories, branches, date range and whether private repositories are authorised. Use read-only access unless the user expressly requests a repository change. Do not expose access tokens, private source code or confidential repository content in outputs. Avoid cloning or transmitting more content than the task requires.

## Legal-use rules

Reconcile repository evidence with employment, contractor, assignment and licence documents. A contributor record does not establish employment status, authorship of every component or transfer of rights. An absent licence file does not by itself establish infringement. Record inaccessible repositories and incomplete history as information gaps.

## Fallback

Request a repository export, relevant logs, dependency manifests, licence files or contributor report. Continue from the supplied materials and mark live repository checks outstanding.
